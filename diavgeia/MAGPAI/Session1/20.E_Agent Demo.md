# Demo 20.E - Agent Demo

## Slide Intent

Show the MAGPAI Agent Demo as the agentic version of the chatbot workflow.

This demo corresponds to the site demo:

```text
docs/demo/magpai-agent-demo-v1.1.html
```

## Say This

The chatbot demo answered a question.

The agent demo shows a broader workflow.

An agent does not only produce text.

It can follow a goal, create a plan, choose tools, act, observe results, reason over those observations, and then answer.

The visual flow is:

```text
Goal -> Plan -> Tool -> Action -> Observation -> Reasoning -> Answer
```

In this demo, MAGPAI uses business data and can also attempt an email action through the email tool.

That is the difference between a simple answer and an agentic workflow.

## Demo Action

Open the Agent Demo.

Click `Run Agent`.

Point out:

- The agent state.
- The plan steps.
- The selected tool.
- The action panel.
- The observation.
- The final answer.
- The email tool status.

If the email server is not configured or not running, frame that as a tool-environment condition, not a failure of the reasoning flow.

## Transition

This closes the practical demo chain.

We started with tokens and ended with an agent workflow that can plan and use tools.

## Key Points

- An agent wraps model output in a workflow.
- The workflow includes planning, tool use, observations, and reasoning.
- Tool status matters because agents interact with external systems.
- The agent demo builds directly on the chatbot demo.
- This is the bridge from model mechanics to enterprise automation.

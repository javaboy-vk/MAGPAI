# Demo 14.A - Vocabulary Training Demo

## Slide Intent

Show how text training builds the tokenizer vocabulary before a model can reliably convert a prompt into token IDs and vectors.

This demo corresponds to the site demo:

```text
docs/demo/Vocabulary_Training_Demo_v2_10.html
```

## Say This

We have just seen that a token ID selects a row from the embedding table.

Now we will step back one level and ask where those token IDs come from.

Before the model can use token IDs, the tokenizer needs a vocabulary.

In this demo, each training sentence adds or updates tokens:

```text
sentence -> tokenizer -> vocabulary tokens -> token IDs -> token vectors
```

The important point is that the vocabulary is not just a list of English words.

It can contain normalized tokens and subword pieces.

For example, `increased` can become:

```text
increas + ed
```

And `increasing` can become:

```text
increas + ing
```

That lets the tokenizer reuse meaningful pieces instead of needing a completely separate entry for every word form.

## Demo Action

Open the vocabulary training demo.

Press `Enter` to train the next sentence.

Point out three things as the demo advances:

- New tokens appear in the vocabulary table.
- Repeated tokens increase their seen count.
- Each trained sentence becomes an ordered sequence of token IDs.

When the demo reaches the final sentence, the model is ready to convert the question into token IDs and corresponding vectors.

## Transition

Now that we have seen text vocabulary training, we can look at the same idea in a visual model.

Images also need tokens, but the tokens are visual patches and learned visual concepts instead of text pieces.

## Key Points

- Tokenizers need a vocabulary before token IDs are useful.
- The vocabulary may contain subword pieces, not only whole words.
- Training sentences add new tokens and update token counts.
- A sentence becomes an ordered sequence of token IDs.
- Token IDs are what later retrieve embedding vectors.
